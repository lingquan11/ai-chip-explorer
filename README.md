# AI 芯片方向探索与科研构思

为 AI 芯片方向的初学者提供一位对话伙伴：先了解你的背景和目标，再帮助你认识不同方向、尝试轻量任务，或围绕科研 idea 展开探索。默认面向中国大陆大学生；对话方法也可结合用户提供的其他行业资料使用。

**状态：第一版草稿。** 方向推荐、岗位描述和科研想法都需要结合个人情况及资料进一步验证。已开展初步角色扮演模拟；独立多轮测试与真实用户验证仍待完成。

## 可以做什么

- **认识方向**：先看简明全景，再通过对话探索自己的兴趣和条件。
- **体验方向**：尝试中文轻量任务，并在过程中逐步辨认哪些工作方式吸引你。
- **探索科研 idea**：从零寻找候选问题，或带着已有想法来讨论、查找相关研究和设计初步验证。
- **切换行业**：提供自己的文件、网页或论文链接，或要求 AI 在工具可用时查找资料。实际读取范围取决于运行环境。

输出是探索建议，不是就业预测、能力测评或科研创新性证明。涉及就业时应检查岗位所在地区和发布时间；文献检索有范围限制，找不到结果不等于无人研究。

## 开始使用

本项目优先面向 Codex；其他 agent 的兼容性尚未验证。下面是预期的用户级安装方法，**尚待在目标环境实测**：

1. 将本仓库中的 `skills/ai-chip-explorer` 文件夹复制到 Codex 用户级技能目录，保留 `SKILL.md` 和整个 `references` 文件夹。常见路径是 Windows 的 `%USERPROFILE%\.codex\skills\ai-chip-explorer` 或 macOS/Linux 的 `~/.codex/skills/ai-chip-explorer`；如设置了 `CODEX_HOME`，以该目录下的 `skills` 为准。
2. 如果目标目录已经存在同名技能，先核对内容，不要直接覆盖。
3. 重新打开 Codex 会话，让它重新发现技能；输入 `$ai-chip-explorer` 并描述需求。具体发现和调用效果需要在实际环境中验证。

初次对话可以直接说：

```text
$ai-chip-explorer 我是电子信息专业大一，对 AI 芯片感兴趣，但不清楚有哪些方向。请先帮我了解，再设计一个轻量体验。
```

也可以带着科研想法开始：

```text
$ai-chip-explorer 我关注矩阵计算的数据搬运，有一个初步想法：……请先了解我的基础和条件，再帮我分析它。
```

或者切换行业：

```text
$ai-chip-explorer 我想探索机器人领域，附件和链接是我准备的资料。请说明实际读到的内容，并帮我梳理方向。
```

## 对话会是什么样？

下面是 [cases/](cases/README.md) 里浅层与 2026-10-29 深度模拟中，较能对应真实痛点的几种回应（均为角色扮演记录，不代表已验证的稳定表现）。

### 零基础、怕负担：先问时间与设备，再安排纸笔短体验

电子信息大一、几乎只会一点 Python、不想买硬件或读厚书时，会先弄清每周能投入多少时间，再用 15–30 分钟量级的纸笔任务体验「同一种计算能否少记中间结果」；若你说不懂算子，会用乘二加一这类直观例子，并在你反馈「找差异有意思、数数有点机械」时调整下一步，而不是一次定方向。

[阅读完整对话](cases/test-beginner.md)

### 不想做题却关心就业：打开招聘页，但不拿一家公司代表行业

零基础用户拒绝手算、只想知道大陆岗位是否都要很强的电路和数学时，助手会按本地资料点名打开一家公司的招聘页，写出当次读到的学历与技能条目、查阅时间，并标明没有发布日期、样本只有这一页——就业问题被限制在「这一页能回答什么」，而不是泛泛预测行业。

[阅读完整对话](cases/runs/2026-10-29-深度模拟/scenario-01-rerun.md)

### 已有 idea：沿你的问题收窄，新颖性留待检索

带着「减少矩阵乘法数据搬运」这类想法、只有普通 CPU 和约一周时，会保留待检验的假设，区分芯片数据流与 CPU 小实验的边界，并整理 idea 卡片；在尚未检索时明确「新颖性未知」，给出可执行的检索关键词，而不是把常见思路说成空白。

[阅读完整对话](cases/test-existing-idea.md)

### 没有 idea：按条件给候选起点，不包装成创新

对数据在芯片里如何流动好奇、两周不能流片、只有普通电脑时，会给出两个范围有限的学习型候选（例如分块与片上存储、阵列利用率），各自说明优点与简化模型的局限；你若担心「只是课本里的分块」，会承认重叠可能很大，并把「先理解机制」和「以后再找科研差异」分开。

[阅读完整对话](cases/test-no-idea.md)

### 打磨科研题：题目留在你的表述上，文献与手算分开记账

想优化注意力里 Q、K 分数的数据搬运、且不要改成普通矩阵乘法时，在用户追问后给出检索式与当次读到的摘要级文献，并写明未读全文、不能证明新意；你自己手算出的读写次数与助手演示的计数分开记录，避免把演示结果当成你的结论。

[阅读完整对话](cases/runs/2026-10-29-深度模拟/scenario-03.md)

### 方向不明或觉得练习无聊：改口、停下，不把一次体验写成定论

学过编程和数字电路却不知选哪条路、讨厌查 bug 或觉得入门题太直白时，会按你更耐受的任务选入口，并在你说无聊或时间不够后停止加题；「对输入比改程序轻」与「喜欢硬件」不会被合并成一条兴趣，一次太容易的练习也不会被写成适合某方向。

[阅读完整对话](cases/runs/2026-10-29-深度模拟/scenario-02-rerun.md)

### 换行业且无资料：不混用 AI 芯片知识，无检索时不编出处

想探索农业机器人却没有知识库、环境不能联网时，会说明未读到你的文件、不能把芯片方向资料当该领域事实；仍可用纸笔拆解「如何定义识别问题、在假设场景里找会失败的情况」，并接纳「暂不想写程序」——同时把粗分方向标为未核实猜测，而不是行业地图。

[阅读完整对话](cases/test-other-domain.md) · [无资料时承认划分依据不足](cases/runs/2026-10-29-深度模拟/scenario-05.md)

### 只信读到的内容：笔记里的随口断言会被放下

切换到其他行业并粘贴自备笔记时，若要求只根据实际读到的文字说话，会列出读到的条目，并拒绝把无出处的话（例如「变黄就等于缺水」「还没有任何研究」）当成事实或方向建议。

[阅读完整对话](cases/runs/2026-10-29-深度模拟/scenario-05-notes.md)
