# AI 芯片方向探索与科研构思

为 AI 芯片方向的初学者提供一位对话伙伴：先了解你的背景和目标，再帮助你认识不同方向、尝试轻量任务，或围绕科研 idea 展开探索。默认面向中国大陆大学生；对话方法也可结合用户提供的其他行业资料使用。

**状态：第一版草稿。** 方向推荐、岗位描述和科研想法都需要结合个人情况及资料进一步验证。已开展初步角色扮演模拟；独立多轮测试与真实用户验证仍待完成。

## 可以做什么

- **认识方向**：先看简明全景，再通过对话探索自己的兴趣和条件。
- **体验方向**：尝试中文轻量任务，并在过程中逐步辨认哪些工作方式吸引你。
- **探索科研 idea**：从零寻找候选问题，或带着已有想法来讨论、查找相关研究和设计初步验证。
- **切换行业**：提供自己的文件、网页或论文链接，或要求 AI 在工具可用时查找资料。实际读取范围取决于运行环境。

输出是探索建议，不是就业预测、能力测评或科研创新性证明。涉及就业时应检查岗位所在地区和发布时间；文献检索有范围限制，找不到结果不等于无人研究。

## 开始使用

本项目优先面向 Codex；其他 agent 的兼容性尚未验证。下面是预期的用户级安装方法，**尚待在目标环境实测**：

1. 将本仓库中的 `skills/ai-chip-explorer` 文件夹复制到 Codex 用户级技能目录，保留 `SKILL.md` 和整个 `references` 文件夹。常见路径是 Windows 的 `%USERPROFILE%\.codex\skills\ai-chip-explorer` 或 macOS/Linux 的 `~/.codex/skills/ai-chip-explorer`；如设置了 `CODEX_HOME`，以该目录下的 `skills` 为准。
2. 如果目标目录已经存在同名技能，先核对内容，不要直接覆盖。
3. 重新打开 Codex 会话，让它重新发现技能；输入 `$ai-chip-explorer` 并描述需求。具体发现和调用效果需要在实际环境中验证。

初次对话可以直接说：

```text
$ai-chip-explorer 我是电子信息专业大一，对 AI 芯片感兴趣，但不清楚有哪些方向。请先帮我了解，再设计一个轻量体验。
```

也可以带着科研想法开始：

```text
$ai-chip-explorer 我关注矩阵计算的数据搬运，有一个初步想法：……请先了解我的基础和条件，再帮我分析它。
```

或者切换行业：

```text
$ai-chip-explorer 我想探索机器人领域，附件和链接是我准备的资料。请说明实际读到的内容，并帮我梳理方向。
```

## 对话会是什么样？

我们设计了四位不同背景的**模拟用户**，试着让 AI 按这个 Skill 的方法与他们对话。

### 不知道从哪里开始

一位模拟用户对“为什么程序有时快、有时慢”感兴趣，但只有普通电脑，也不想一开始就读很多书。

助手先安排了一个纸笔小任务。用户说自己喜欢分析差异，却觉得重复计数无聊；助手便建议他下一步尝试比较数据是怎样被重复使用的。

[阅读完整对话](cases/test-beginner.md#完整模拟对话)

### 有想法，但不知道怎么做

另一位模拟用户想研究“减少矩阵计算时的数据搬运”，但只有一周时间，也没有专门的芯片设备。

助手帮他把想法缩小成一个可以先用纸笔探索的问题，并整理成研究想法卡片。同时，它说明还需要查阅论文，不能直接认定这个想法有创新性。

[阅读完整对话](cases/test-existing-idea.md#完整模拟对话)

### 没有想法，或者想换个领域

- **没有科研想法：** 助手根据模拟用户对数据流的兴趣和现有条件，提出两个方向供选择。[查看对话](cases/test-no-idea.md#完整模拟对话)
- **想了解其他领域：** 模拟用户转向农业机器人，但没有提供资料。助手说明信息尚未核实，再从一个简单的识别问题开始探索。[查看对话](cases/test-other-domain.md#完整对话)

> **这些只是初步模拟。** 每个场景只运行了一次，由同一个 AI 扮演用户、助手并评价结果；测试时没有联网，也没有实际验证 Codex 自动加载。四个场景都还有待改进，不能代表真实用户的体验或证明稳定性。
>
> [查看测试结果与不足](cases/README.md) · [了解如何继续测试](evaluation/README.md)

### 一次更长的模拟

2026-10-29 另有一批 9–11 轮的角色扮演，目录是 [cases/runs/2026-10-29-深度模拟/](cases/runs/2026-10-29-深度模拟/summary.md)。上面四段仍是更早的短对话。这一批同样由同一个 AI 扮演用户、助手和评价者，没有在 Codex 里加载 Skill，不能说明效果稳定。

其中一次，模拟用户不想做题，只想知道门槛高不高。助手打开了本地地图里点名的一个招聘页，写明查阅时间和“岗位条目没有发布日期”，并承认当天给不出方向建议。[阅读这一次](cases/runs/2026-10-29-深度模拟/scenario-01-rerun.md)。另一次，用户坚持讨论注意力里的数据搬运。助手列出了当次只读过摘要的三篇文献，没有把它们写成“已经证明没有新意”。[阅读这一次](cases/runs/2026-10-29-深度模拟/scenario-03.md)。

多数场次没有检索。拒绝做题的那一次没有替代任务。这些是模拟记录里的缺口，不是已经修好的能力。
