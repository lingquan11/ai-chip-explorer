# AI 芯片方向探索与科研构思

为 AI 芯片方向的初学者提供一位对话伙伴：先了解你的背景和目标，再帮助你认识不同方向、尝试轻量任务，或围绕科研 idea 展开探索。默认面向中国大陆大学生；对话方法也可结合用户提供的其他行业资料使用。

**状态：第一版草稿。** 方向推荐、岗位描述和科研想法都需要结合个人情况及资料进一步验证。已开展初步角色扮演模拟；独立多轮测试与真实用户验证仍待完成。

## 可以做什么

- **认识方向**：先看简明全景，再通过对话探索自己的兴趣和条件。
- **体验方向**：尝试中文轻量任务，并在过程中逐步辨认哪些工作方式吸引你。
- **探索科研 idea**：从零寻找候选问题，或带着已有想法来讨论、查找相关研究和设计初步验证。
- **切换行业**：提供自己的文件、网页或论文链接，或要求 AI 在工具可用时查找资料。实际读取范围取决于运行环境。

输出是探索建议，不是就业预测、能力测评或科研创新性证明。涉及就业时应检查岗位所在地区和发布时间；文献检索有范围限制，找不到结果不等于无人研究。

## 开始使用

本项目优先面向 Codex；其他 agent 的兼容性尚未验证。下面是预期的用户级安装方法，**尚待在目标环境实测**：

1. 将本仓库中的 `skills/ai-chip-explorer` 文件夹复制到 Codex 用户级技能目录，保留 `SKILL.md` 和整个 `references` 文件夹。常见路径是 Windows 的 `%USERPROFILE%\.codex\skills\ai-chip-explorer` 或 macOS/Linux 的 `~/.codex/skills/ai-chip-explorer`；如设置了 `CODEX_HOME`，以该目录下的 `skills` 为准。
2. 如果目标目录已经存在同名技能，先核对内容，不要直接覆盖。
3. 重新打开 Codex 会话，让它重新发现技能；输入 `$ai-chip-explorer` 并描述需求。具体发现和调用效果需要在实际环境中验证。

初次对话可以直接说：

```text
$ai-chip-explorer 我是电子信息专业大一，对 AI 芯片感兴趣，但不清楚有哪些方向。请先帮我了解，再设计一个轻量体验。
```

也可以带着科研想法开始：

```text
$ai-chip-explorer 我关注矩阵计算的数据搬运，有一个初步想法：……请先了解我的基础和条件，再帮我分析它。
```

或者切换行业：

```text
$ai-chip-explorer 我想探索机器人领域，附件和链接是我准备的资料。请说明实际读到的内容，并帮我梳理方向。
```

## 对话会是什么样？

更多完整记录见 [cases/](cases/README.md)。下面是模拟对话里较典型的几种「痛点 → 回应」。

### 零基础、怕负担：先问时间与设备，再安排纸笔短体验

**痛点：** 大一、几乎没写过代码，每周时间少，怕 AI 芯片「太重」、要买板卡或啃厚书。  
**亮点：** 先问你能投入的时间与设备，用普通电脑上的 15–30 分钟纸笔任务感受「同一种计算能否少记中间结果」；不懂算子时用乘二加一这类直观例子；你说「找差异有意思、数数有点机械」时，下一步会跟着你的感受走，而不是一次替你定方向。

[阅读完整对话](cases/test-beginner.md)

### 不想做题却关心就业：用可查的招聘页回答「门槛高不高」

**痛点：** 完全零基础、不想手算，但想知道大陆岗位是不是都要很强的电路和数学，并担心助手拿一家公司代表整个行业。  
**亮点：** 按资料打开真实招聘页，写出当次读到的学历与技能条目和查阅时间，把问题收束在「这一页实际写了什么」，同时避免把一家公司说成行业全景。

[阅读完整对话](cases/runs/2026-10-29-深度模拟/scenario-01-rerun.md)

### 已有 idea：沿你的问题收窄，并整理可继续核查的卡片

**痛点：** 带着「减少矩阵乘法数据搬运」等想法，只有普通 CPU、时间约一周，又怕方向太宽或被人做过。  
**亮点：** 保留你的核心假设，区分「芯片里数据流」与「CPU 上先做小实验」各自能回答什么，整理 idea 卡片，并给出可执行的文献检索关键词，方便你下一步自己核对相近工作。

[阅读完整对话](cases/test-existing-idea.md)

### 没有 idea：按你的时间与工具给能动手的候选

**痛点：** 想找科研题但完全没有头绪，只有两周、不能流片、一台普通电脑。  
**亮点：** 根据你关心的现象（例如数据在芯片里怎么流动）给出两个可先做的小方向（如分块与片上存储、阵列利用率），说明各自适合探索什么问题；若你担心「只是课本内容」，会支持「先理解机制、再对照文献找差异」两条路并行。

[阅读完整对话](cases/test-no-idea.md)

### 打磨科研题：题目按你的表述保留，文献与手算分开记

**痛点：** 想优化注意力里 Q、K 分数的数据搬运，不要被偷换成普通矩阵乘法，并需要有人帮查有没有相近研究。  
**亮点：** 在你追问后给出检索式与读到的相近文献条目；你自己手算出的读写次数与助手演示的计数分开记录，idea 仍停在你原来的表述上。

[阅读完整对话](cases/runs/2026-10-29-深度模拟/scenario-03.md)

### 方向不明或觉得练习无聊：按偏好换入口，说停就停

**痛点：** 学过编程和数字电路却不知选哪条路；讨厌查 bug，或觉得入门题太直白、时间只够一刻钟。  
**亮点：** 按你更耐受的任务选体验入口；你说无聊或时间不够时停止加题，不把「对输入比改程序轻」直接写成「适合硬件」，也不把一次太简单的练习当成方向结论。

[阅读完整对话](cases/runs/2026-10-29-深度模拟/scenario-02-rerun.md)

### 换行业且无资料：从你自己的观察继续，而不是硬套芯片话术

**痛点：** 想探农业机器人等领域，没有知识库、也没有论文链接，还担心助手把 AI 芯片那套原样搬过来。  
**亮点：** 明确切换到新行业后不再把芯片方向的练习或岗位描述当成该领域事实；仍可用纸笔拆解「如何定义识别问题、在假设场景里找会失败的情况」，并尊重你「暂不想写程序」的偏好；你纠正「户外还行 ≠ 喜欢导航」时会改口，从你亲眼见过的现象（例如叶子被挡）接着聊。

[阅读完整对话](cases/test-other-domain.md) · [从观察现象继续](cases/runs/2026-10-29-深度模拟/scenario-05.md)

**无资料时勿硬套芯片优化话术（模拟对照）：** 维护场次中，未加载 Skill 的助手曾把 GEMM/NPU 映射到农业路径；读更新 `knowledge-pack.md` 后的补测里助手在第 2 轮明确拒绝（[改前](cases/runs/2026-10-31-自主评估-补测/scenario-06a-other-without-skill-sep.md) · [改后](cases/runs/2026-10-31-自主评估-补测/scenario-06a-other-no-kb-retest-after-fix.md)，**同一 AI 子代理**，**不等于**真实稳定性）。

### 只信读到的内容：自备笔记里无出处的断言会被放下

**痛点：** 切换行业时粘贴自己的笔记，怕助手把笔记里的随口话当成事实或入行建议。  
**亮点：** 只根据实际读到的条目展开；像「变黄就等于缺水」「还没有任何研究」这类没有出处的句子，不会升级成结论或方向推荐。

[阅读完整对话](cases/runs/2026-10-29-深度模拟/scenario-05-notes.md)

### 查 idea 时写清「读到哪、没验证什么」（模拟）

**痛点：** 没有 idea 或已有 idea 时，怕助手搜几篇论文就断言「没人做过」或「一定能发」。  
**亮点：** 加载 Skill 的场次按 [检索记录模板](evaluation/retrieval-record-template.md) 写检索式、查阅时间、abs 摘要阅读范围与未能验证项；**首次检索默认不超过 3 条**可核对来源，用户未口头上限时助手仍应自克制（2026-10-31 角色分离复测，**同一 AI / 子代理模拟**，未 Codex 加载，**不等于**真实稳定性）。
