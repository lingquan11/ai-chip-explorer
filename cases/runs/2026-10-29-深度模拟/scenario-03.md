## 2. 完整逐轮对话

### 第 1 轮

**模拟用户：** 我有个想法，想减少注意力里面 Q 和 K 相乘时的数据搬运，也许能让加速器更省事。能帮我打磨吗？先别换成别的题目。

**助手：** 可以。先保留你的题目：注意力计算里，Q 和 K 相乘这一步的数据搬运。它会不会让加速器更省事，现在是待查的假设，不是已经看到的结果。

你说的搬运，是分数矩阵太大、不想整块存下来，还是 Q、K 本身被反复读取？用你自己的话讲就行。

**助手：** 记下了：问题是注意力分数要不要整块保存，不是去改一个通用矩阵乘法库。你只见过示意图，所以我们先不假设你学过具体硬件结构。

你打算用什么机器、大概有多少时间？这一步是为了避免把验证设计得你做不了。

**助手：** 机器和时间先固定成：两周、CPU、不做 CUDA。在这些条件下，做不了加速器芯片，最多做一个把规则写清楚的小例子。

### 第 4 轮

**模拟用户：** 现在查。你别因为查到矩阵乘法的论文，就把我的题改掉。我关心的是推理，不是训练。你凭什么刚才说不能判断？

**助手：** 刚才不能判断，是因为当时没查。下面是查过之后、仍然有限的结果。检索时间 2026-10-29 20:15（CST），检索式是 `attention accelerator dataflow memory traffic QK matrix 2024`。只读了三页的摘要和引言开头，没有读全文。

### 第 5 轮

**模拟用户：** 听不懂 I/O、systolic、bandwidth。用大白话。我怀疑你找的这三篇是不是真的和我的题有关，还是只是都带了 attention 这个词。

**助手：** 用这三篇摘要里能对应上的话来说，不引入你没问过的结构名词。

- 第一篇在问：算注意力时，慢的那一层存储要被读多少次、写多少次。这和“搬运”有关。它讨论的是复杂度上界和下界，不是帮你在笔记本上做实验。
- 第二篇在做专门跑注意力的硬件设计，关心中间结果要不要占越来越大的片上存储。这和“分数要不要存下来”同类，但是硬件项目，不是两周 CPU 作业。

相关，是主题上的相关：都在看注意力的中间数据要占多少存储、要搬多少。我没有核对它们是不是同一种“不存整张分数表”的做法。只因为标题里有 attention 就当成同一题，会过头；反过来把它们说成无关，也不符合摘要。全文没读，这个判断停在摘要级。

### 第 6 轮

**模拟用户：** 先收窄到纸上能查的程度。给我一个很小的数，我自己算分数。别一开始就上芯片。

**助手：** 只算分数，不谈芯片。一个 Query：`[1, 2]`。两个 Key：`[3, 4]` 和 `[5, 6]`。分数等于对应位置相乘再相加。

请算出这两个分数。这一步只检查算术，还不统计搬运。

### 第 7 轮

**模拟用户：** 1×3+2×4=11，1×5+2×6=17。然后呢？我已经觉得再往下数内存会很难。

**助手：** 11 和 17 按这个定义是对的。下面若要谈搬运，必须先写死计数规则，否则数字没有意义。规则只覆盖“分数表”这一层，故意很窄：

- 方案甲：把 11 和 17 写入数组，记 2 次写；再把这两个数读出来比较大小，记 2 次读。这一层共 4 次。
- 方案乙：不建数组。算出 11，先当作当前较大值；算出 17，发现更大，就换掉。分数数组的读写是 0 次。
- 不统计读取 Query 和 Key，不计标量。所以方案乙不是“整个计算零搬运”。

你已经觉得难，可以不自己数。上面这 4 和 0 是我按规则演示的，不是你的实验结果，也不能拿去和那三篇论文比。

### 第 8 轮

**模拟用户：** 0 次听起来像在骗人。两周也不够做芯片。你是不是把验证设计得太大了？

**助手：** 0 次容易误导。它只表示没有读写那张分数数组，Query 和 Key 该读还是要读。若把这句话理解成“加速器不再搬运数据”，规则就被用错了。你的怀疑成立。

两周和只有 CPU，确实做不了芯片。前面若让人联想到要复现论文或做硬件，那个验证太大了。收成一次纸笔能结束的检查：

- 预测：在上面的窄规则里，方案乙的分数数组读写少于方案甲。
- 会削弱它的结果：只要把读取 Query、Key 也算进同一套规则，两者的差距就可能变小，甚至结论不再是“乙显然更省”。这一步我们还没做。
- 笔记本上的运行时间不能证明加速器的搬运量。

今天可以停在 11 和 17，加上这条还没做完的计数警告。

### 第 9 轮

**模拟用户：** 我还是担心已经有人做了。你查到的那些摘要，算不算已经证明我的想法没有新意？

### 第 10 轮

**模拟用户：** 请整理一张 idea 卡片。如果已经被研究了，我这两周是不是就没意义？

**助手：** 有人研究过，不等于你这两周没有学习意义。它只表示不能把练习写成创新。贡献是否成立，本次检索不够判断。

**idea 卡片**

- **题目与研究问题：** 在一个事先写明的计数规则下，不保存两个注意力分数，和先写入再读出，分数数组的读写次数有什么差别？这是学习用的窄问题，不是芯片题目。
- **背景和价值：** 用户在课上看过注意力示意图，关心推理时不要把 Query 和所有 Key 的分数都存下来。价值目前是帮助用户看懂“少存一张表”不等于“整体少搬运”。还不能写成应用价值或创新价值。
- **已有工作：** 2026-10-29 20:15（CST）一次网页检索。读了 Saha & Ye，arXiv:2402.07443，摘要级；Nayak 等 FuseMax，arXiv:2406.10491，摘要级，ACM 页未通读；Sohn、Zhang & Olukotun，`https://arxiv.org/html/2404.16629`，摘要级。主题相近，做法是否相同未核对。未读全文，未覆盖中文资料，不能证明新颖或“已被做完”。
- **候选思路和假设：** 窄规则下，不建分数数组会少掉那一层的读写。关键前提是不把 Query、Key 的读取算进去。另一个解释是：把那些读取算进去之后，优势会缩小。
- **预期和验证：** 预期是方案甲 4 次、方案乙 0 次，且这组数字只属于分数数组。用户没有独立完成计数，数字是助手演示。若把 Q、K 的读取纳入同一规则后差距消失，原假设在更完整的规则下不成立。笔记本计时不能当作加速器证据。
- **条件与限制：** 两周、笔记本 CPU、不会 CUDA、只见过示意图。不做芯片，不复现论文实验。
- **下一步：** 最小的一步是由用户自己决定要不要把 Q、K 的读取写进规则，再重数一次。在那之前，不能下结论。文献上的下一步是挑一篇全文，对照它有没有“不物化整张分数矩阵”的做法；本次没有做。

### 第 11 轮

**模拟用户：** 卡片里的 4 和 0 先别算我的结果。我只承认 11 和 17 是我算的。这样还算把问题打磨了吗？

**助手：** 算打磨到一个更小的问题，但不算你完成了验证。你独立算出的只有两个分数：11 和 17。4 和 0 从你的结果里拿掉，卡片里应视为助手的演示，待你自己重做。

现在的研究问题可以留着，状态是“规则还没有被用户验收”。两周若只用来把规则改清楚并自己数一遍，范围是匹配的。把它写成新的加速器结构，范围不匹配。

## 6. 暴露的问题与改进建议

- Skill 的体验库没有注意力计数范例。助手临时写的规则必须极端声明边界，否则“0 次”会失真。建议以后若要支持这个常见 idea，在 `experiences.md` 增加一个带完整读写表的可选例子，先不要改 `SKILL.md`。

- 卡片里的演示数字和用户结果必须分开。第 11 轮的拒绝应当保留，不能在总结里写成用户完成了搬运实验。
