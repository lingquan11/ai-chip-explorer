# 场景 02：学过一些编程和数字电路，不确定方向

> **同一 AI 三角色自评。** 模拟用户、被测助手和评价者是同一个 Cursor cloud agent。存在自评偏差。这不是独立盲测，不是真实用户反馈，也不是在 Codex 里加载 Skill。

## 1. 测试条件与模拟角色

- 日期：2026-10-29（Asia/Shanghai）。
- 模型：Cursor cloud agent，系统标识 Grok 4.7。无更细构建号，不编造版本号。
- Skill 提交：`28302bd2b1aa6a22dab7311ef237eb20c29c22ee`。
- 加载方式：没有在 Codex 中加载。助手只依据 `SKILL.md`、`references/domain.md`、`references/experiences.md`。
- 联网：本场**未检索**。`domain.md` 里的 TVM 链接没有在本次打开。文件头写的“网页查阅日期：2026-10-29”是文件自带文字，不等于本场重新打开过网页。
- 轮次：10 轮。第 2 次见 [scenario-02-rerun.md](scenario-02-rerun.md)。
- 模拟用户（虚构）：学过 C++ 和基础数字电路；做过课程实验，不喜欢写实验报告；每周大约 2 小时，当场只剩不到 20 分钟。会纠正兴趣判断、要求解释术语、质疑推荐依据，并表示喜欢比较做法、不喜欢估算次数。

## 2. 完整逐轮对话

### 第 1 轮

**模拟用户：** 我学过一点编程，也碰过数字电路，但不确定 AI 芯片里哪个方向适合我。

**助手：** 你已经有两块可以用来试的背景，不过“学过”还不等于“适合哪一条”。编程更靠近把计算排给硬件，数字电路更靠近把功能写成可检查的逻辑。另外还有数据怎么在计算里复用、模型精度和存储怎么一起看。今天不用选定。

你做这些练习时，哪一种时刻比较不烦？若还想不起来，就说最近做过什么。

### 第 2 轮

**模拟用户：** 我用 C++ 写过小程序。数字电路做过课程实验，但我不喜欢写实验报告。每周大概两小时。

**助手：** 暂时可以有两个入口，都还不是结论：用你写过小程序这一点，试“同一种计算换一种做法”；用你做过数字电路这一点，试“把输入列全并检查”。你不喜欢写报告，所以第二个入口不该做成实验报告。

你想先试哪一个？

### 第 3 轮

**模拟用户：** 你好像默认我会喜欢检查电路，因为我学过数字电路。其实我不确定。实验报告让我很烦，我也不知道自己是不是喜欢验证。

**助手：** 这个纠正成立。上过数字电路课，不能推出你喜欢验证。我把第 2 轮里的第二个入口收回，不再把它当成你的倾向。

剩下一个仍可试的，是比较两种计算写法会不会得到同一个结果。它不用写报告。你也可以两个都不试。你要不要先试比较写法？

### 第 4 轮

**模拟用户：** 可以试试比较写法。但是我听不懂算子、RTL、数据布局。能不能说人话？我现在不到 20 分钟。

**助手：** 这 20 分钟只做一件事，不涉及 RTL 和数据布局。把“算子”先理解成对一批数做的一个操作，例如每个数乘二再加一。真实框架里的定义更细，这里用不上。

x = [1,2,3,4]。目标是每个数变成 2x+1。写法一：先把四个数都乘二，存成一张中间表，再逐个加一。写法二：拿到一个数，立刻乘二加一，不存整张中间表。请先算两种写法的最终四个数，看它们是否一样。计数先不做。

### 第 5 轮

**模拟用户：** 两种都是 3、5、7、9。算数还行。我想知道你为什么觉得这能代表编译器方向。依据是什么？

**助手：** 它不能代表编译器方向的工作日。依据只有本地文件：`experiences.md` 的练习 C 用这个例子感受“少存一张中间表”；`domain.md` 把编译器和算子写成“怎样把计算安排到硬件上”，并把练习 C 当作入门体验。`domain.md` 还写了一个 TVM 教程链接，文件头的查阅日期是 2026-10-29。本场没有打开那个链接，所以不能把文件里的日期说成我今天核对过网页。

因此，依据是教学练习的设计说明，不是岗位调查，也不是你适合这个方向的证据。你已经算出两种写法结果相同。按资料里的提问，你更喜欢比较这两种写法，还是更想估算它少了哪些读写？

### 第 6 轮

**模拟用户：** 我比较喜欢比较两种做法，不喜欢估算次数。你要是现在让我数访问次数，我会觉得无聊。

**助手：** 那就停在“结果相同、过程不同”，不进入数次数。喜欢比较、不喜欢计数，只描述这次练习，不能说明你适合或不适合编译器。真实编译器还会遇到缓存和自动优化，这次模型没有涉及，本场也没有测量。

20 分钟里还要不要看一个词，就是“中间表”在写法一里具体指 t = [2,4,6,8]？看完就停。

### 第 7 轮

**模拟用户：** 不用看了，这个我能想象。时间不够，今天就到这。你这个建议是不是太早了？我只说学过 C++，你就带到编译器。

**助手：** 带得偏早。第 1–2 轮把 C++ 小程序当成“可以试练习 C”的理由，这只是入口假设。你没有说过想做编译器。第 5 轮也说明了这个练习不是编译器工作本身。你的质疑成立：不能从“写过小程序”走到“适合编译器”。

今天到此为止。留下的只有：两种写法都得到 [3,5,7,9]；你更喜欢比较，不想计数；数字电路实验不能解释成你喜欢验证。

### 第 8 轮

**模拟用户：** 那我到底适合哪边？你现在好像又什么都不说了。

**助手：** 今天判断不了适合哪边。要说的是：一次 20 分钟的比较，加上你不喜欢实验报告，都不够支持方向结论。这不是把问题退回去，而是现有信息不够。

若下次还有 20 分钟，可以只做一件新的事：你讲一个自己写过的 C++ 小程序，我们看你当时是在改算法，还是在查为什么结果不对。那个谈话仍然不是测评。现在不必开始。

### 第 9 轮

**模拟用户：** 我的小程序就是读入几个整数求平均。查错的时候很烦，比较两种写法还稍微好一点。我不确定这算不算喜欢。

**助手：** 求平均这个事实我记下。查错让你烦，比较两种写法稍微好一点，但你自己不确定算不算喜欢。这三句同时成立，我不把“稍微好一点”改写成稳定兴趣。

它和芯片方向的关系也还没建立：求平均不是芯片任务。下次若继续，仍然只比较工作感觉，不评定方向。

### 第 10 轮

**模拟用户：** 行。你先别推荐岗位，我也不想再做题了。

**助手：** 不推荐岗位。本场没有查招聘。今天没有新的题目。

便条：学过 C++ 和数字电路；不喜欢实验报告，所以上课不能当成喜欢验证；20 分钟内比较了两种计算写法，结果都是 [3,5,7,9]；不想数访问次数；觉得从 C++ 连到编译器太早，这个连接已经撤回。方向未选。

## 3. 角色是否分离及主要局限

没有分离。助手知道练习 C 的参考结果，用户“刚好算对”不能视为独立解题。没有打开 TVM 页面，没有检索岗位或论文，没有计时。第 2 次运行的用户偏好不同，不能把本场结果合并成稳定结论。

## 5. 需求是否解决、未解决问题

用户拿到一次可停的比较，并看到“学过数字电路 / 写过 C++”被撤回为方向结论。适合哪边没有解决，本场也不该解决。

未解决：若既不喜欢计数、又不想再做题，下一步是什么；编译器或验证的真实工作是否如练习所示；20 分钟以外的体验。

## 6. 暴露的问题与改进建议

- 助手容易把已学课程当成入口，用户会觉得被提前归类。第 3 轮和第 7 轮收回了这个归类。建议在案例中保留这种收回，不要把第一次暂定说法写成稳定人设。
- 文件自带的查阅日期容易被说成“今天核对过链接”。第 5 轮做了区分。以后凡是引用 `domain.md` 的 URL，都应写明本场有没有打开。
- 用户喜欢比较、拒绝计数时，练习 C 的后半会整段落下。这不是失败对话，但完成标准会落空。记录时不要把前半完成写成整题完成。
