# 四个轻量体验：先感受，再按需补知识

四个体验是纸笔或任意文本编辑器可完成的入门练习，无需购买硬件、安装 FPGA 或训练大型模型。建议分成两次，每次约 15–30 分钟，但这是**设计估计，并非用户实测时间**；可按用户情况拆分。下面的参考答案供助手核对，先让用户尝试，不要直接揭晓。数值与计数是教学模型，不代表真实硬件性能。各体验的用户完成率、实际时间及跨环境体验均尚未验证。

## A：架构与数据流——追踪矩阵计算

**角色感受：** 像架构研究者一样，考虑同一数据如何被重复使用。

**准备：** 纸笔，懂加法和乘法；矩阵乘法可由助手先用单个元素解释。

**第一次：** 给出 A = [[1,2],[3,4]]、B = [[5,6],[7,8]]。解释 C[i,j] 是 A 第 i 行与 B 第 j 列对应元素乘积之和。让用户手算 C[0,0]，再算完整矩阵 C。

**穿插提问：** “你更喜欢算出结果，还是追踪哪些数字被重复使用？为什么？” 如果感觉困难，演示一个乘加后再继续。

**第二次：** 列出计算 C 第一行需要 A 的哪些数字，找出 A[0,0] 在这一行的两个结果里分别参与了什么乘法；再找 B[0,0] 在两行中如何被使用。讨论若把重复用到的数据放在计算附近，可能减少什么搬运；不假设因此必然提升实际速度。

**完成标准：** 能算出 C，指出至少一个 A 或 B 的元素被两个输出复用，并用自己的话解释复用的直觉。

**参考答案：** C = [[19,22],[43,50]]；A[0,0] 分别乘 B[0,0] 和 B[0,1]；B[0,0] 分别乘 A[0,0] 和 A[1,0]。这个练习只展示数据复用，不模拟完整脉动阵列或真实芯片。参考：[MIT 课程](https://csg.csail.mit.edu/6.5930/info.html)，[SCALE-Sim](https://github.com/scalesim-project/SCALE-Sim)。

## B：数字硬件——设计并验证一位加法器

**角色感受：** 将功能定义成明确的输入输出，再检查所有输入情况。

**准备：** 纸笔；输入 a、b 只能是 0 或 1。解释输出 s 表示结果的低一位，c 表示进位。

**第一次：** 列出四种输入 (0,0)、(0,1)、(1,0)、(1,1)，算出每组的 s 和 c。用户如果不懂二进制，先说明 1+1 写作二进制 10。

**穿插提问：** “列举所有情况并寻找遗漏的过程让你感觉有趣、无聊，还是需要更具体的例子？”

**第二次：** 观察什么时候 s=1、什么时候 c=1；用自然语言写规则，并用全部四组输入重新检查。若愿意，可再用 [HDLBits](https://hdlbits.01xz.net/wiki/Main_Page) 学习简单逻辑；网站是否可访问以实际情况为准。

**完成标准：** 四组结果正确，能说出两条输出规则，并理解验证要覆盖不同输入。

**参考答案：** 四组 (s,c) 依次为 (0,0)、(1,0)、(1,0)、(0,1)；s 在输入不同时为 1，c 仅当两输入都为 1 时为 1。此任务是逻辑设计入门，不等同完整 RTL 开发或时序验证。

## C：编译器与算子——比较中间数据搬运

**角色感受：** 面对同一个计算，比较不同执行方式对资源的影响。

**准备：** 纸笔；数组 x = [1,2,3,4]。目标：逐个计算 y = 2x + 1。

**第一次：** 方案一先计算整个中间数组 t = 2x，再计算 y = t + 1。方案二每次取一个 x，直接计算对应 y，不保存完整 t。算出两种方案的 y 是否一致。

**穿插提问：** “你更享受找等价变换，还是估算它节省了哪些操作？有没有哪一步不清楚？”

**第二次：** 在约定的简化模型里，每次读取或写入一个数组元素记为一次访问；不计常数、寄存器、缓存或临时标量。方案一统计读 x、写 t、读 t、写 y；方案二统计读 x、写 y。比较总次数。

**完成标准：** 能算出一致的 y，并按明确的模型分别统计访问次数；能指出该模型没有证明真实运行会更快。

**参考答案：** y = [3,5,7,9]；方案一 4+4+4+4=16 次，方案二 4+4=8 次。真实编译器可能自行优化，缓存及硬件使实际表现不同。此练习只是理解融合思路，并非实现真正的编译器。参考：[TVM 优化教程](https://tvm.apache.org/docs/how_to/tutorials/customize_opt.html)。

## D：算法与硬件协同——观察量化误差

**角色感受：** 同时考虑表示精度和存储需求，不预设牺牲精度一定值得。

**准备：** 纸笔或计算器；定义示例量化 q = 四舍五入(4x)，还原值 x' = q/4。它只是演示，不代表所有量化方案。

**第一次：** 对 x = [0.1,0.4,0.8] 分别计算 q 和 x'，比较每个值与原值的差距。必要时先由助手示范第一个数。

**穿插提问：** “当存储更省、结果却不完全准确时，你更想研究误差，还是想知道它对硬件有什么好处？”

**第二次：** 假设原数据每个值占 32 位，q 存在范围允许的 8 位整数中；只计算这三个数本身的存储位数，暂不计比例参数、对齐等额外开销。讨论更小存储并不自动意味着推理更快，实际精度与速度要测量。

**完成标准：** 算出量化及还原结果，描述误差和简化存储估算，并说出至少一个尚未验证的影响。

**参考答案：** q = [0,2,3]，x' = [0,0.5,0.75]，绝对误差约 [0.1,0.1,0.05]；简化估算原数据 96 位，整数数据 24 位。比例参数等实际开销不在估算内。[PyTorch 量化教程](https://docs.pytorch.org/ao/stable/eager_tutorials/static_quantization.html)可作延伸，具体接口和适用性需按版本核实。

## 体验回顾

询问具体时刻：哪一步想继续探索，哪一步感到疲惫或困惑？若体验不佳，先讨论原因可能来自任务、难度、工具或方向，再由用户选择调整或尝试其他体验。一次纸笔任务不能代表真实工作全貌，也不能单独证明某个方向适不适合用户。
