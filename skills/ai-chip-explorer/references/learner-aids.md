## 矩阵乘预测对照

先预测再看数据。时间均为设计估计，用户可随时停；不写或改 C++，不接计数器，不看汇编。

**预测（约 10 分钟）：**
1. N=256 时三个矩阵共多少字节？请先说元素类型，再与自己 CPU 的缓存容量比较；可查任务管理器或 CPU-Z，注意区分单核和合计。
2. ikj 比 ijk 快还是慢？N=64 与 N=256 哪个差距更大？
3. N≤256 时 blocked 相对 ikj 是赢还是输？为什么？

**取数（至多 20 分钟）：**先在独立空目录运行现成程序并保留输出；跑不了就贴旧中位数表；旧表也没有就只做预测并写进续学记录。该项目的 `summarize_medians.py` 只读取固定的历史归档，不会汇总刚运行的 CSV；新结果需查看其输出或自行整理。若程序支持直接调整规模，可多跑一档，否则跳过。

**对照（至多 25 分钟）：**并排列出预测和实际观察。下面每项都是候选而非结论；请挑 1–2 项，写「现在能否区分、需要什么证据」。

| 候选解释 | 能否区分、靠什么 |
| --- | --- |
| 工作集已放得下（假设，未验证） | 待填 |
| 分块额外循环和边界开销（假设，未验证） | 待填 |
| 编译器对 ikj 处理更好，例如向量化（假设，未验证） | 待填 |
| 计时噪声（假设，未验证） | 待填 |
| 计数模型未算的项（假设，未验证） | 待填 |

至少一项可写「现在无法区分」。不要将任何一项说成唯一原因；说某一层更少或零次时同轮给整体计数。最后各写一句「能说」和「不能说」。

类比：CPU 缓存通常由硬件自动管理；很多加速器的片上缓冲需软件或编译器显式安排，具体芯片须核实。

以上只是纸笔模型和实测的差距候选，不追究 CPU 底层原因。

## 读问三步

共三步，随时说停。材料限定教材、博客的一小节或 README；超过三页只选一节。没有材料时，用「那个小例子」：先存中间结果与直接算 2x+1。先问读到哪里：标题、图、摘要、一节还是全文？记录来源和阅读范围。

| 话术 | 用户最小回答 | 兜底 |
| --- | --- | --- |
| 它想解决什么问题，拿什么当尺子？ | 问题或尺子 | 给候选填空，允许跳过 |
| 结论靠什么前提？ | 一个前提 | 指回读到的句子，允许不确定 |
| 改掉前提，尺子可能怎样变？ | 一个猜想 | 给候选填空，不代答 |

原样保留用户回答，由用户确认「学习性小假设（未检索）」。只答完前两步也算有效研读：说一行「你已经得到：……」。连续两步答不出就一行小结并结束；说停或时间不够即停。首次无聊停止此活动，按主文件允许替代或结束；第二次无聊结束，不换第三种活动。

用户想继续才用 idea-card 和既有首次至多三条检索规则；已有工作与用户待验证假设分开，不据此否定假设。

## 计数规则与算力带宽体验

这是理解数据复用的极简理论模型；不含缓存层次、流水线停顿和延迟，不代表真实 NPU 的周期表现；数字不是性能预测。用户拒绝计算或觉得无聊时不触发。

涉及搬运、存储或「所以更快吗」时，先说明上面的边界并请用户确认或改一次以下规则：
1. 写清目标计算、数据形状、存储层和比较对象。
2. 约定每次读写一个元素计一次，临时量是否计入须说明。
3. 分开记录各层读、写及整体总数；「零次」同句限定层级，同轮给整体。
4. 标记每个数字是用户完成还是助手演示；结果不是实测。
5. 改第 X 条假设时明确「第 X 条变了，以下数字作废」，重数并并排显示新旧数字。

仅当用户完成已有矩阵或数组体验并问为什么快慢时，可邀请他做「算力与带宽对照」；最多 15 分钟（设计估计）、最多三次小计算，可拒绝。它仍是理解复用的极简理论模型，不含缓存层次、流水线停顿和延迟，不代表真实 NPU 的周期表现，数字不是性能预测。

假设教学用虚拟机每周期最多 P 次乘加、最多搬 B 个数（不是真实芯片）。沿用刚才体验的计算量和搬运数，请用户算每搬一个数做几次乘加；比较 P 与 B 乘复用强度，判断模型中先遇到哪种约束。再由用户修改复用或 B，重新计算并观察约束是否翻转；不强迫翻转，不把模型结论当实际速度。
