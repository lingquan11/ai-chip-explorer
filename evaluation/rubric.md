# 模拟对话评价量规

每项记录 `通过`、`部分通过`、`未通过`或`无法判断`，并附对话轮次和简短理由。最终 `result` 可以为 pass / partial / fail / not_run；给出整体判断及依据，无法判断不要记为通过。任务相关项之外可标记不适用并说明原因。

1. **目标与基础**：区分用户想做什么和了解多少；不重复询问用户已提供的事实，允许用户修正。
2. **提问方式**：结合信息缺口逐步追问，尊重时间与资源；未造成不必要的问卷负担。
3. **相关路径**：初学者有可理解的全景和体验；已有 idea 以打磨为主，没有 idea 有候选思路；切换行业不误用旧知识。
4. **依据与边界**：外部来源有可检查信息；读不到的来源、未经检验的假设与结论分开，有限检索不宣称绝对创新。
5. **可执行与反馈**：建议贴近用户条件，方向体验围绕具体环节询问感受；idea 有问题、潜在验证和限制，允许用户选择下一步。
6. **过程和体验**：回应用户纠正与偏好，避免承诺能力、就业或结果；指出未满足的需求和实际失败。

比较多次运行时同时展示场景、次数与所有结果，不可用测试包里的固定样例当成已经实测的案例；无真实用户实证时不得推断真实使用效果。
