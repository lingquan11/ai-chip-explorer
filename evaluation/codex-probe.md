# Codex 加载与打包完整性探针

用途：把「Skill 在 Codex 里是否生效」变成有日期的实测事实。这是真实试跑前的闸门。**本文件只放 evaluation/，不进 skills/。** 仓库作者尚未在 Codex 中执行过本探针，下面所有结果栏都是 `not_run`，不是通过。

## 记录头（每次执行都填）

Codex 版本：待填　系统：待填　技能目录实际路径：待填　执行日期（含时区）：待填　执行者：待填

无 Codex 权限或无法打开会话时，整表记 `not_run`，不记 pass。

## 第一阶段：极简通断（约 30 分钟，V1 必做）

| 编号 | 做什么 | 预期（来自仓库文件） | 结果 |
|---|---|---|---|
| P0 | 按 README 复制 `skills/ai-chip-explorer`，重开会话，输入 `$ai-chip-explorer` | 技能被识别；记路径与版本 | not_run |
| P1-a | 问：领域地图的更新日期是哪天？ | 2026-10-29（见 `domain.md`） | not_run |
| P1-b | 问：注意力两层计数的固定算例，两个分数和各层合计分别是多少？ | 分数 11 与 17；分数层 4 次对 0 次；合计 12 次对 8 次，且同轮说明「0 次」只指分数数组（见 `experiences.md`） | not_run |
| P1-c | 问：idea 卡片里「预期和验证」要写哪些内容？ | 预测什么、对照什么、如何测量、什么结果会削弱假设（见 `idea-card.md`） | not_run |

填写规则：结果只写 `pass` / `fail` / `not_run`，另写一行依据（助手原话摘录或轮次）。

## 判读表

| 现象 | 倾向的解释 |
|---|---|
| P0 失败 | 路径或版本问题 |
| P0 通过，P1-a 至 P1-c 全失败 | `references/` 没有被读取 |
| 仅 P1-d 失败 | 打包缺口：技能内链接指向文件夹外的 `evaluation/` |
| P1 通过，第二阶段不稳 | 规则读到了，但行为不稳定 |

若证实打包缺口，只在记录里列可选修复，不在本轮修改。

## 第二阶段：完整探针（约 2 小时，第 2 周补，V1 不要求）

- P2：三个复测开场——拒绝计算又拒绝读岗位页；说听不懂术语；担心 FlashAttention 已有人做。每场 2–3 个可观察信号：对用户不说内部编号；两层计数在同一轮给出；不否定用户的假设。
- P3：同样三个开场，不加载 Skill 作对照。
- 每场用 `evaluation/record-template.json` 存一份 JSON，用 `evaluation/summarize.py` 汇总。
- 非确定性处理，开始前三选一并写明：固定随机种子跑 2 次；或 3 次中至少 2 次出现算通过；或 3 次中仅 1 次出现记「不稳定」。**严禁只跑 1 次就记 pass 或 fail。**
- 完成后，把 STATUS 里「Codex 安装……待实际测试」改成带日期的实测陈述，只写实际观察到的。

## 未验证
