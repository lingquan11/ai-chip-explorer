# 模拟测试与人工交接

状态：测试包已编写；尚无在此归档的真实模拟运行结果。它不自动调用 AI，也不代表真实用户研究。

## 手动测试

1. 使用能读取 Skill 的代理，加载 `skills/ai-chip-explorer/SKILL.md` 及其引用的资料。记录 Skill 版本或 Git 提交、目标模型、工具可用情况。
2. 由另一 AI 扮演 [模拟角色](personas.md)，或由人代替模拟角色。将角色的完整设定交给扮演者，将「第一句话」发给被测 Skill；不要提前把隐藏信息和预期结果交给被测 Skill。
3. 模拟角色只在被问及或自然对话需要时披露信息，不能替 Skill 提供答案。每轮原样转发消息，直到形成建议、体验或明确标记信息不足；保存原始多轮对话。一个模拟角色可以重复运行，记录每次模型配置和区别；不要只保留最好的运行。
4. 由人工或独立 AI 按 [评价量规](rubric.md) 检查对话；记录证据所在轮次、失败项和限制。有联网检索时按 [检索记录模板](retrieval-record-template.md) 填写来源与阅读范围。使用 `record-template.json` 将每次运行保存为单独 JSON。结果 `pass`、`partial`、`fail`、`not_run` 均需要保留；无证据时说明原因，不推测通过。
5. 执行 `python evaluation/summarize.py path/to/record.json`，多个 JSON 可以作为多个参数。工具检查必填字段并汇总提交的评价；它不审查评价真伪，不评分，也不生成模拟对话。完整对话只留在原始 JSON，检查隐私后再决定公开。

请检查模拟者、被测 Skill、评价者是否由同一模型担任；共享模型可能导致评价偏差。尽可能记录每个角色所用模型、版本和运行条件。模拟案例可以显示表现和失败例子，不能证明真实用户效果或通用有效性。不能联网、无法读取资料时要据实记录，不应声称完成文献查证。

## 测试本工具

从仓库根目录运行 `python -m unittest discover -s evaluation -p "test_*.py" -v`。`summarize.py -` 可从标准输入读取一个 JSON，方便集成；输出为 UTF-8。测试包含虚构数据，只检验程序行为，不是 Skill 测试结果。
